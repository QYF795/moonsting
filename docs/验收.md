# 验收材料 · moonsting

> 面向 2026 MoonBit 黑客松的验收清单：能力矩阵、实测数据、一键复现、已知限制。
> 所有数字都可以用本文里的命令在本机重跑；写死的数字都注明了执行参数与日期。
> 最后核对：2026-11-24（v0.7.0）。

## 1. 项目是什么

给 MoonBit 补上模糊测试这一层：**喂坏字节，拿回一个最小反例、一份报告和一条能粘进仓库的回归测试**。零第三方依赖，同一份代码编译到 `wasm-gc` / `js` / `native` 三个后端。

```
moonsting run  --target varint --seed 1 --max-execs 50000
moonsting run  --target boom   --isolate          # 崩溃隔离
moonsting run  --target csv    --corpus-dir .corpus --cov-report
moonsting replay   --target varint --hex 92ffffff0f
moonsting minimize --target varint --hex 92ffffff0f00010203
```

## 2. 能力矩阵

| 能力 | 状态 | 用哪条命令验证 |
|---|---|---|
| 变异引擎：havoc / 结构化 / 字典 / splice / 边界 | ✅ | `run --target json --max-execs 20000` |
| 结构化变异：按输入形状分派（JSON token / **protobuf 字段** / **TLV 记录** / base64 / %XX / CSV） | ✅ | [README](../README.md) 的「结构化变异」一节 |
| 语料库：去重、锦标赛选择、trim | ✅ | 任何一次 run 的 `corpus` 行 |
| 四种 oracle：smoke / metamorphic / 往返 / 双实现差分 | ✅ | `list` 的 oracle 列 |
| ddmin 最小化（进程内） | ✅ | `minimize --target varint --hex ...` |
| 隔离模式下的批量最小化 | ✅ | `--isolate --target varint`（`--no-shrink` 可关） |
| finding 按"形状"去重 | ✅ | `varint` 报 2–3 条而不是几十条 |
| 报告：text / jsonl / 自包含 html / 回归测试生成 | ✅ | `--json` `--html` `--emit-test` |
| 语料持久化（编号文件，无需 readdir） | ✅ | `--corpus-dir` 连跑两次 |
| 语料最小化（集合覆盖，148 → 10 覆盖不变） | ✅ | `cmin --corpus-dir DIR` |
| 跨后端差分（同一输入，wasm-gc vs native 输出必须一致） | ✅ | `cross --target utf8 --max-execs 120` |
| 进程隔离 + 崩溃输入定位（native） | ✅ | `--isolate --target boom` |
| 并行 worker | ✅ | `--isolate --jobs 8 --batch-size 4096` |
| 手写插桩覆盖反馈 + 形状回退 | ✅ | `--cov-report` |
| 插桩报告：命中 id 段、未到达分支、未声明 id，两种执行模式都支持 | ✅ | `--cov-report` |
| 对 MoonBit 标准库自身做 fuzz（`@json`、`@bigint`） | ✅ | `run --target stdjson` / `run --target bigint` |
| CI 钩子（有 finding 非零退出） | ✅ | `--fail-on-finding` |
| CI 自吃狗粮（干净 target 必须仍为 0 finding） | ✅ | `.github/workflows/ci.yml` 的 dogfood 步骤 |
| CI 在 GitHub macOS runner 容量不足时不误报 | ✅ | macOS 两条腿为 advisory（`continue-on-error`），Ubuntu/Windows 仍阻断 |
| 维护自检：15 项一条命令，含跨后端差分与两个标准库 target | ✅ | `script/healthcheck.sh`（CI 每周一自动跑） |
| 编译器覆盖率产物接线 | ❌ | 普通二进制不落盘，见 [架构.md](架构.md) D1 |

## 3. 实测数据

本机：Windows 11 / Ryzen。3.1 与 3.4 为 2026-11-20 重测。

### 3.1 十七个带 oracle 的 target（各 20,000 次执行，seed 1，wasm-gc）

| target | oracle | findings | 独立签名 | 备注 |
|---|---|---|---|---|
| `varint` | diff | **2** | 16 | 32 位截断，真 bug（跑满 200k 时报 3 条） |
| `decimal` | roundtrip | **1** | 28 | 溢出导致自我拒绝 |
| `json` | metamorphic | 0 | 219 | 空白不变性成立 |
| `csv` | smoke | 0 | 91 | 无崩溃 |
| `utf8` | diff | 0 | 130 | 两个独立实现零分歧 |
| `protobuf` | roundtrip | 0 | 148 | 非最小 varint、超宽 tag 等全部拒绝 |
| `rle` | roundtrip | 0 | 31 | 宽度纪律单独校验 |
| `urlenc` | roundtrip | 0 | 20 | 严格拒绝非规范编码 |
| `tlv` | roundtrip | 0 | 10 | 长度算术一致（插桩只有 10 个 id，早饱和） |
| `base64` | roundtrip | 0 | 4 | 可达路径本来就少 |
| `csvstrict` | roundtrip | 0 | 53 | 严格拒绝多余引号、CR、空尾行 |
| `arff` | comment-invariant | 0 | 38 | 注释不改变摘要 |
| `fixed` | roundtrip | 0 | 14 | 列宽几何、前导零 |
| `ini` | comment-invariant | 0 | 27 | 分区外的键值 |
| `props` | roundtrip | 0 | 16 | 空格与等号必须转义 |
| `stdjson` | consistency | 0 | 66 | **MoonBit 标准库的 `@json`**，见 [findings.md](findings.md) §10 |
| `bigint` | consistency | 0 | 107 | **标准库的 `@bigint`**；输入上限 256 位，见 §10.7 |

签名数随 seed 与执行数变化，不是"越少越好"：`tlv` 只有 10 是因为它只有 10 个插桩 id。

### 3.2 吞吐（2026-11-17 测得，native 为 release）

| 配置 | 吞吐 |
|---|---|
| 进程内，wasm-gc | 201,207 exec/s |
| 进程内，native release | 191,938 exec/s |
| 进程内，js (node) | 61,919 exec/s |
| 隔离，单 worker | 2,626 exec/s |
| 隔离 + `--jobs 8 --batch-size 4096` | **8,336 exec/s** |

2026-11-20 的标准库长跑另有一组数（wasm-gc 131,752 / native 42,507 / js 41,109 / 隔离 7,010 exec/s），差异来自 target 本身的开销，见 [findings.md](findings.md) §5.6。

### 3.3 确定性

同 seed、同执行数，三个后端的 JSONL **逐字节相同**（含 finding 的 exec 序号）：

```bash
moon run cli --target wasm-gc -- run --target varint --seed 1 --max-execs 50000 --json > a.jsonl
moon run cli --target native  -- run --target varint --seed 1 --max-execs 50000 --json > c.jsonl
diff a.jsonl c.jsonl   # 无输出
```

更强的一条证据：`stdjson` 在三个后端各跑 20 万次，**语料都是 90 条 / 88 个签名**，逐项相同（findings.md §5.6）。

### 3.4 插桩覆盖（2026-11-20 实测，4,000 次执行）

```bash
moon run cli --target native -- run --target protobuf --max-execs 4000 --cov-report
# coverage : 15 ids hit (920-931, 933-934, 941)
# unreached: 932, 940, 942 (3 of 18 declared branches never taken)
```

同一个命令在其他 target 上：

| target | 结果 |
|---|---|
| `csv` | `branches : all 10 declared ids were reached` |
| `utf8` | `unreached: 816, 822 (2 of 24 declared branches never taken)` |
| `rle` | `unreached: 960, 962 (2 of 13 declared branches never taken)` |

隔离模式下同参数输出**完全相同**（worker 把命中 id 带回父进程并合并）。

## 4. 两个"度量"结论（可解释性素材）

1. **结构化变异要证明的是"变异体仍然合法"，不是"语料更多"**：用后者衡量会得出"没效果"的错误结论（语料条数受插桩粒度限制）。
2. **JSON 变异的合法率 46% → 99%**：转折点不是调参，而是把操作单位从"token"换成"成员"（复制整对 `k:v`、删除连 key 一起）。中途还发现自己的检查器太软（只数括号配平），把 `{"a":}` 当成合法，报出了虚高的 66%。

第三条同类结论写在 [DEVLOG](../DEVLOG.md) D19：给"识别出格式时"提高结构化变异份额，实测反而少了 2 个签名，已回滚。

## 6. 已知限制（不掩饰）

1. **没有自动插桩**：写 target 的人要自己在分支上放 `@cov.hit(id)`、在 catalog 里声明；没插桩就静默回退到形状反馈。
2. **语料目录遇缺口截断**：`corpus-0007.hex` 缺失时只加载 1–6；写入不收缩。
3. **隔离模式崩溃用例不做 shrink**：缩它要对每个候选起进程；非崩溃用例可以。
4. **并行是亚线性的**：`--jobs` 必须配 `--batch-size`，组合见 README。
5. **覆盖报告的"未到达"依赖声明**：声明过的 id 未命中就是未到达（精确）；没声明的 target 只能报"观测区间内的空洞"，那种情况仍可能把未分配的号段算进去。
6. **TLV 的"字段级"只是记录级**：能改长度、类型、增删记录，但不会改记录内部的 payload 编码（那需要知道语义）。
7. **标准库体检只覆盖自洽性**：`@json` 的 `valid`/`parse`/`stringify` 三个入口，不覆盖 `derive(FromJson)`，也不等于规范符合性。
8. **Windows native 不进 CI**（需要 MSVC），由本机 demo 脚本覆盖。
9. **CI 的 macOS 腿是 advisory**：GitHub 的 arm64 runner 偶发拿不到实例（15 分钟后报 `job was not acquired`），这是基础设施故障不是代码故障，所以不让它把整条流水线染红；macOS 结果仍在 job 列表里可见。
