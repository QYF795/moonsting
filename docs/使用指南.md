# 使用指南

从"装好"到"接上自己的解析器"的完整路径。所有命令的输出都是本机真实输出，可直接对照。

## 1. 安装

**从 mooncakes 引入（推荐）**

```bash
moon add QYF795/moonsting
```

**从源码**

```bash
git clone https://github.com/QYF795/moonsting
cd moonsting
moon check --target wasm-gc
moon test  --target native
```

三个后端都能跑：`wasm-gc`（默认，最快）、`js`（node）、`native`（需要 C 工具链；`--isolate` 只在 native 可用）。

## 2. 五分钟上手

```bash
# 看有哪些 target
moon run cli --target wasm-gc -- list

# 跑一个：5 万次执行
moon run cli --target wasm-gc -- run --target json

# 换 seed 复现同样的一轮
moon run cli --target wasm-gc -- run --target json --seed 0
```

输出长这样（`varint` 的例子，它有一个真 bug）：

```
target   : varint  (oracle: diff(varint.fast,varint.ref))
execs    : 50000 in 1189 ms  (42052 exec/s)
corpus   : 20 entries, 18 buckets, 14 novel inputs
findings : 3
  [mismatch] varint  input=ffff80ff0f (5B)
        expected v:4292886527 got v:-2080769
```

四行分别回答：跑了什么、多快、探索了多少条路径、发现了什么。

## 3. 子命令

| 命令 | 作用 |
|---|---|
| `run` | 主命令：变异 + 执行 + oracle + 语料 + 报告 |
| `list` | 列出 target 和它们的 oracle |
| `replay --target NAME --hex HEX` | 重新跑一条输入，验证 finding 可复现 |
| `minimize --target NAME --hex HEX` | ddmin 收缩到最小反例 |
| `worker --target NAME --batch FILE --out FILE` | 内部用：执行一个批次文件（`--isolate` 会调它） |
| `cmin --target NAME --corpus-dir DIR` | 语料最小化：保留仍覆盖全部 id 的最小子集，见 §9 |

## 4. `run` 的全部参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--target NAME` | `json` | 用哪个 target |
| `--seed N` | `0` | 变异随机种子；同 seed 结果逐字节一致 |
| `--max-execs N` | `50000` | 执行次数上限 |
| `--time 5s` | 无 | 时间预算（`s` / `ms` 后缀），与 `--max-execs` 谁先到算谁 |
| `--max-input N` | `4096` | 单个输入的最大字节数 |
| `--max-findings N` | `16` | 找到这么多就停 |
| `--seed-input HEX` | 无 | 追加种子（可重复），会与 target 自带种子合并 |
| `--corpus-dir DIR` | 无 | 语料目录：读进来，跑完写回去（编号文件） |
| `--corpus-max N` | `4096` | 从目录里最多加载多少条 |
| `--isolate` | 关 | 每批在子进程里跑，崩溃变成 finding 而不是杀死整个 run |
| `--batch-size N` | `512` | 一个子进程执行多少条（只在 `--isolate` 下有效） |
| `--jobs N` | `1` | 并行 worker 数（只在 `--isolate` 下有效） |
| `--no-shrink` | 关 | 关掉最小化 |
| `--json` | 关 | 输出 JSONL（每条 finding 一行，机器可读） |
| `--html` | 关 | 输出自包含 HTML 报告 |
| `--emit-test` | 关 | 把最小反例生成可粘贴的 `moon test` 块 |
| `--dump-corpus` | 关 | 把语料以 hex 行打印出来 |
| `--cov-report` | 关 | 追加插桩覆盖率：命中的 id 段 + 未到达的分支 |
| `--fail-on-finding` | 关 | 有 finding 时以非零码退出（给 CI 用） |
| `--quiet` | 关 | 只输出 finding |

## 5. 三种运行模式

| 模式 | 命令 | 吞吐（本机） | 什么时候用 |
|---|---|---|---|
| 进程内 | `run` | ~20 万 exec/s | 默认。语义 bug（结果错）用它 |
| 隔离 | `--isolate` | ~2.6 千 exec/s | 怀疑会 panic / 越界，需要崩溃定位 |
| 并行隔离 | `--isolate --jobs 8 --batch-size 4096` | ~8.3 千 exec/s | 隔离但想快一点 |

隔离模式的成本来自进程启动：**`--jobs` 必须和 `--batch-size` 一起调**，批次太小的话启动开销吃掉全部收益。

## 6. 接上自己的解析器

target 的 body 是 `(Bytes) -> String`：输出什么都可以，oracle 只看这个字符串。

```moonbit
import {
  "QYF795/moonsting/api",
  "QYF795/moonsting/core",
  "QYF795/moonsting/targets",
}

test "fuzz my parser" {
  let target = @core.Target::new(
    "mypkg.parse",
    [b"{\"a\":1}", b"[]", b"\"x\""],
    fn(input) { my_parse(input) },
  )
  let case = @targets.Case::new(
    "mypkg",
    target,
    @core.Oracle::Custom("roundtrip", fn(_input, output) {
      // 返回非空字符串表示违反性质
      if output == "" {
        "empty output"
      } else {
        ""
      }
    }),
  )
  let run = @api.fuzz_case(case, @core.Config::default().with_max_execs(20000))
  println(run.summary())
}
```

跑内置 target 更简单：

```moonbit
let run = @api.fuzz("json", @core.Config::default())   // Run?
```

### 三种现成 oracle

| oracle | 判据 | 适合 |
|---|---|---|
| `Oracle::Same` | 只要不崩就算过 | 冒烟：有没有 panic / 越界 |
| `Oracle::Custom(name, fn)` | 自己写，返回非空 = 失败 | 往返、不变性、自校验 |
| `Oracle::Diff(a, b)` | 两个实现必须给出同一个字符串 | 差分：第二遍实现比写规格便宜 |

### 别忘了插桩

在目标的分支里调 `@cov.hit(id)`，引擎就会用"本次执行命中集合的指纹"判新颖性；不插桩也能跑，只是回退到"输出形状"反馈。插桩后还要在 catalog 里声明用到的 id（`declared_for`），`--cov-report` 才能回答"哪些分支从没被走到"。
## 7. 复现与回归

```bash
# 1. 找到反例
moon run cli --target varint -- run --target varint --json > findings.jsonl

# 2. 复现
moon run cli --target varint -- replay --target varint --hex ffff80ff0f

# 3. 缩小
moon run cli --target varint -- minimize --target varint --hex 92ffffff0f00010203

# 4. 固化成测试
moon run cli --target varint -- run --target varint --emit-test
```

`--json` 的输出在三个后端之间逐字节相同，所以 CI 里可以直接 diff。

## 8. 在 CI 里用

```bash
# 有 finding 就失败
moon run cli --target native -- run --target json --max-execs 20000 --fail-on-finding

# 回归门禁：语料目录持久化，第二轮只跑新路径
moon run cli --target native -- run --target json --corpus-dir .corpus

# 覆盖率报告
moon run cli --target native -- run --target protobuf --cov-report
```

## 9. 语料最小化

```bash
moonsting cmin --target protobuf --corpus-dir .corpus --out .corpus-min
moonsting cmin --target protobuf --corpus-dir .corpus --dry-run   # 只看数字
moonsting cmin --target protobuf --corpus-dir .corpus --json      # 机器可读
```

输出：

```
corpus   : 148 inputs
coverage : 16 of 16 ids
kept     : 10 inputs (10 files written)
out      : .corpus-min
```

- 判据是"覆盖的 id 集合"，同分优先更短的输入，结果确定。
- 没有插桩的 target 退回输出形状（输出 + 输入长度档），仍会保留每个形状的一个代表。
- **需要 native 后端**：读写文件靠 `proc`，wasm-gc / js 上会打印提示而不是静默失败。
- `--out` 默认 `.corpus-min`，已存在的目录不会清空（编号文件会覆盖同名）。

## 10. 维护

```bash
script/healthcheck.sh          # 全量：13 项检查
script/healthcheck.sh --quick  # 跳过 native（没装 C 工具链时用）
```

输出是一行一项 `PASS/FAIL`，失败项会打印最后几行输出；全部通过退出码 0，否则非零——可以直接挂到 cron 或 CI。CI 里有一个同名的每周任务。

它检查的不是"新功能"，而是**已有结论有没有被上游推翻**：三个后端的编译与测试、六个应当保持干净的 target、以及两个标准库 target。上游 `@json` / `@bigint` 改动时，这里会先红。

## 11. 常见问题

**Q：跑了 5 万次，0 findings，是不是没生效？**
A：先看 `corpus` 行的第二个数字（签名数）。0 签名说明变异全被拒；几十上百个签名说明在探索，只是没找到 bug。0 finding 本身是结果，不是失败——尤其对往返/差分 oracle。

**Q：target 崩了但没生成 finding。**
A：进程内模式下运行时 trap 会直接终止整个 run。加 `--isolate`。

**Q：`--jobs 8` 反而更慢。**
A：`--batch-size` 太小。每次子进程启动 60–200 ms，`--jobs 8 --batch-size 4096` 是本机的甜点。

**Q：`--cov-report` 说 `none (target is not instrumented)`。**
A：那个 target 没插桩。这是正常状态，引擎会自动回退到输出形状反馈。

**Q：Windows 上 `--isolate` 报错找不到 exe。**
A：`--isolate` 需要 native 后端且当前目录可写（它用 cwd 相对的临时文件）。先 `moon build --target native`。
