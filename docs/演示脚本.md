# 演示脚本（90 秒）

给现场演示或录屏用。五幕，每幕一句旁白 + 一条命令。命令的输出本身就是幻灯片——不需要额外做 PPT。

> 前提：`moon build --target native` 已执行。Windows 用 `_build\native\debug\build\cli\cli.exe`，Linux/macOS 同路径无 `.exe`。

## 0:00–0:10 · 一句话

**说**：「MoonBit 有 test、有覆盖率、有多后端，但没有模糊测试。moonsting 补的是这一层：喂进坏字节，拿回一个最小反例、一份报告，和一条能粘进仓库的回归测试。」

```bash
moonsting list
```

（17 个 target 一行行滚过去，够用了，不用念。）

## 0:10–0:30 · 真 bug

**说**：「这是它抓到的第一个真 bug：32 位 varint 解码器的静默截断。不崩、不报错，只是算错——最贵的那类。」

```bash
moonsting run --target varint --seed 1 --max-execs 50000
```

**指着念**：`expected v:4292886527 got v:-2080769`。

## 0:30–0:50 · 可复现 + 最小化

**说**：「finding 必须能复现，否则不算 finding。replay 独立重算一遍；minimize 把它缩到最小。」

```bash
moonsting replay   --target varint --hex ffff80ff0f
moonsting minimize --target varint --hex ffff80ff0f00010203
```

**指着念**：`from 9B → to 5B`。

## 0:50–1:10 · 崩溃不拖垮运行

**说**：「进程内跑，一个 panic 就会杀掉整个 run。加 --isolate，崩溃变成一条 finding，还告诉你它是批次里第几个输入打死的——所以这里没有二分，逐行 flush 已经把索引给了我们。」

```bash
moonsting run --target boom --seed 1 --max-execs 1500 --isolate
```

**指着念**：`[crash] boom input=de (1B)` 和 `worker exited with code ... on input 9 of 512`。

## 1:10–1:30 · 反馈信号与生态

**说**：「引擎用"本次执行命中集合"的指纹判新颖性；没有插桩的 target 自动回退到输出形状。报告会告诉你哪些分支从没走到——比如 protobuf 这里有两个。最后这个是直接 fuzz MoonBit 标准库自己的 JSON 解析器，5 万条敌意输入，零 panic、零分歧。」

```bash
moonsting run --target protobuf --max-execs 20000 --cov-report
moonsting run --target stdjson  --max-execs 50000
```

**指着念**：`unreached: 940, 942 (2 of 18 declared branches never taken)` 和 `findings : 0`。

## 一页速查

| 秒 | 命令 | 一句话 |
|---|---|---|
| 10 | `list` | 17 个 target |

| 32 | `replay --hex …` | 能复现 |
| 40 | `minimize --hex …` | 9B → 5B |
| 52 | `run --target boom --isolate` | 崩溃被隔离并定位 |
| 70 | `run --target protobuf --cov-report` | 哪些分支没走到 |
| 82 | `run --target stdjson` | 标准库扛住了 |

## 录屏注意

1. **先跑一遍**，把 `_build` 和语料目录预热好，第一次 `moon run` 会编译，会卡 20 秒。
2. 终端字号调到 16–18pt，让 `findings` 那几行能被看清。
3. `--max-execs 50000` 在本机约 1.2 秒；如果机器慢，降到 20000，旁白不变。
4. 不要录 `moon test`（110 个用例滚几十行，观众只会记住"滚得快"）。
